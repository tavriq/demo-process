# SPEC v2: ИИ-аналитик процесса (demo-process)

09.10.2026. Дополняет `docs/SPEC.md` (v1: разбор текста → схема Было/Стало). Всё из v1 остаётся: контракт Process/Improve, расчёт `web/engine.js`, схема, .bpmn, записанные примеры.

Владелец бизнеса отвечает на вопросы голосом или текстом. Схема процесса растёт после каждого ответа. В конце — Было/Стало и короткий отчёт «где теряете часы и рубли, что автоматизировать первым» со ссылкой на 30 суток.

Почему это лучше v1: в четырёх записанных примерах время из текста было у 5 шагов из 54, остальное — допущения. Интервью спрашивает недостающее: сколько заявок в месяц, ставку, минуты на тяжёлых шагах, ожидание между людьми — и что происходит на передаче от одного человека к другому, не пропущены ли там шаги.

## Что видит посетитель (телефон 360 px)

1. В окне процесса вместо «Свой процесс» — блок «Интервью». Старт: «Какой процесс разберём?» — 4 кнопки-подсказки (заявки, счета, возвраты, выход сотрудника) или своя фраза.
2. Вопрос в одну-две строки и под ним ответ: кнопка микрофона (тап — запись, тап ещё раз — отправить, до 30 с) или поле текста до 500 знаков. Счётчик «вопрос 3 из 8» и кнопка «Хватит — строй отчёт» (доступна после 3 ответов).
3. После каждого ответа схема (только «Было») перерисовывается: новые шаги появляются с той же анимацией, что в v1. Под вопросом — что понял код: «записал: 120 заявок в месяц».
4. Конец (8 вопросов, «Хватит» или нет пробелов): схема Было/Стало, как в v1, и карточка-отчёт:
   - часы, рубли и дни на заявку Было → Стало;
   - 2 шага, на которых теряется больше всего (часы × ставка), и почему;
   - что автоматизировать первым и сколько это даёт в месяц;
   - какие цифры из ответов, какие — допущения (подсветка, как в v1);
   - «Скачать .bpmn» (Было, Стало), «Ссылка на отчёт» (копировать), «Обсудить внедрение» (mailto, адрес даёт сайт через опцию mount).
5. Ссылка на отчёт: `/process/#report=<id>` (фрагмент, не query — `?r=` на сайте занят метками каналов). Открывает готовый отчёт без вызова моделей 30 суток.

## Кто что решает

| Что | Кто |
|---|---|
| распознать речь | `STT_MODEL` (`openai/gpt-4o-transcribe` через шлюз, как в demo-voice) |
| скрыть телефоны, почты, ссылки в ответе до записи и до модели | код (`app/pii.py`) |
| черновая схема по всей стенограмме после каждого ответа | `DRAFT_MODEL` (дешёвая, по умолчанию `gemini/gemini-3.1-flash-lite`), JSON по контракту Process |
| проверка черновика (цитаты, числа в цитате, граф) | код (`app/checks.py`, как в v1) |
| **какой вопрос следующий** — пробел с наибольшим приоритетом (таблица ниже) | **код** |
| формулировка вопроса простыми словами по пробелу и имени шага, без чисел | `ASK_MODEL` (= `DRAFT_MODEL`), ответ ≤ 160 знаков; цифры в вопросе код вычищает |
| извлечь из ответа числа для допущений (заявок в месяц, ставка, минуты шага, ожидание) | код (регулярки с единицами из `checks.py`); если не нашёл — модель черновика в поле `answers` |
| финальная схема и «Стало» | `EXTRACT_MODEL` и `IMPROVE_MODEL` из v1 по стенограмме |
| часы, рубли, дни, потери, первая автоматизация и её эффект | код (`web/engine.js`) по допущениям, переопределённым ответами |
| итоговая фраза отчёта без чисел | `IMPROVE_MODEL` (`summary` из v1) |

Почему вопрос выбирает код: на пробах голосового демо 08.10 модель, которой давали выбрать вопрос самой, спрашивала не то (yandexgpt-lite — 3 из 3 раз, claude-haiku-4-5 — 1 из 3).

### Пробелы и их приоритет (код, `app/gaps.py`)

1. Нет старта или конца процесса.
2. Заявок в месяц неизвестно (допущение 100).
3. У шага нет роли или роль «кто-то».
4. У развилки меньше двух веток или ветка никуда не ведёт.
5. Что происходит между шагами X → Y (задача или развилка), где работа переходит к другой роли: нет ли там ещё шагов. Сначала ребро, по которому заявка проходит чаще (посещения X × доля ветки), при равенстве — по порядку шагов. Не больше 2 таких вопросов за интервью. Стоит до ставки: шаги определяют схему, а у ставки есть разумное допущение.
6. Ставка часа неизвестна (допущение 700 ₽).
7. Минуты неизвестны у шага с наибольшей долей часов (по текущему расчёту).
8. Ожидание неизвестно на передаче между ролями с наибольшим вкладом в дни.
9. Сколько людей в роли с наибольшей загрузкой.

Один пробел — один вопрос. Тот же пробел дважды не спрашивается. Ответ «не знаю» закрывает пробел, остаётся допущение.

Почему пробел 5: замер 13.10 — шагов эталона найдено 28 из 42, связей сохранено 18 из 52; все 8 вопросов ушли на числа, ни один — на пропущенные шаги; «выход сотрудника» между прогонами давал от 3 до 8 шагов из 11. Шаги чаще всего прячутся на передаче между людьми.

- Пробел 5 спрашивает не число: его ключ — `between.1`, `between.2` (уникальный), в `answered` он не попадает.
- Id шагов черновика модельные и после перерисовки сдвигаются, поэтому пару код помнит по именам шагов (сходство названий, как при переносе чисел в финал, порог 0,5): ту же пару второй раз не спрашивает — и её же, разделённую шагами из ответа (X → новый шаг, новый шаг → Y).
- Ответ по сути «ничего, сразу передают» закрывает пробел без перерисовки черновика, как «не знаю». Любой другой ответ перерисовывает черновик: новые шаги встают между X и Y со следующими свободными id, id прежних шагов не меняются.

## Контракт API (`/api/process/`, в дополнение к v1)

```
POST /interviews                         {"topic": "заявки"|"счета"|"возвраты"|"выход"|null, "text": "своя фраза"|null}
  → 201 {"id", "question": {"n":1, "max":8, "text", "gap": "volume"}, "process": null, "budget_left_rub"}
         (gap — ключ пробела: "start_end", "volume", "s3.minutes", "between.1"…)
POST /interviews/{id}/answers            JSON {"text"} или multipart audio (webm/ogg/mp4/mpeg/wav/m4a, ≤ 30 с, ≤ 600 КБ)
  → 200 {"answer_text", "understood": [{"field":"volume","value":120,"unit":"заявок/мес"}],
         "process": Process|null, "flags", "question": {...}|null, "done": false, "steps": [{"name","ms","rub"}]}
POST /interviews/{id}/finish             → 202; дальше GET
GET  /interviews/{id}                    → {"status": "asking"|"building"|"done"|"error", "transcript": [{"q","a"}],
         "process", "improve", "assumptions": {...}, "answered": ["volume","rate","s3.minutes",...], "steps", "totals"}
```

- `assumptions` — те же ключи, что `E.assume()` в engine.js, плюс `minutes`/`wait_hours` по шагам из ответов. Страница считает отчёт сама (engine.js), сервер цифр отчёта не хранит.
- `answered` — ключи пробелов, на которые есть число; `between.N` числа не спрашивает и сюда не попадает.
- Ошибки — как в v1 (`budget`, `rate_limited`, `busy`, `model_format`, `bad_request`), плюс `stt_failed` (не распознал — попросить повторить, вопрос не расходуется).

## Деньги и лимиты

- Худший случай интервью = 8 × (STT + черновик + вопрос) + финал (extract + improve с повтором). Посчитать в `app/pricing.py`, интервью стартует только при остатке ≥ худшего случая, резерв сразу (как в v1). Оценка до замера: текстом ~1–1,5 ₽, голосом ~2,5–3 ₽.
- `DAILY_BUDGET_RUB` общий с v1: 40 ₽ с 12.10 (худший случай интервью 12,70 ₽ держится целиком; при 15 ₽ после 2,30 ₽ трат новые не стартовали). 3 интервью в час с адреса, не больше 2 одновременно. Интервью без ответа 10 минут закрывается.
- Хранение: стенограмма со скрытыми контактами и результат — 30 суток (`RETENTION_DAYS`), аудио не хранится.

## Страница (`web/process.js`, `web/process.css`)

- Новый блок «Интервью» вместо «Свой процесс»; записанные примеры остаются сверху как в v1.
- Микрофон: `MediaRecorder`, тап — старт, тап — стоп, индикатор уровня, без автоотправки по тишине. Нет доступа к микрофону — остаётся поле текста.
- Отчёт — карточка под схемой, все числа из engine.js; рядом с каждым — «из ответа» или «допущение».
- `#report=<id>` при загрузке открывает отчёт без интервью.
- JS окна вместе ≤ 85 КБ несжатого (сейчас 62). Всё от модели и из ответа — `textContent`. `prefers-reduced-motion` как в v1.

## Замер (`evals/interview/`)

- «Владелец-симулятор»: для 4 процессов из `evals/processes.jsonl` модель отвечает на вопросы, видя только скрытое описание процесса и строгие правила (не выдумывать, «не знаю», если в описании нет).
- Метрики по каждому прогону: шаги эталона найдены (тот же `score.py`), связи эталона сохранены (`edges_kept`), сколько вопросов задано и сколько из них «между шагами» (не больше 2), у скольких шагов минуты из ответов против допущений (цель — больше, чем 5 из 54 в v1), вопросов-повторов 0, цифр в вопросах 0.
- `run.py --max-rub`, перед запуском — худший случай в рублях. Живые вызовы — только у владельца репо, в сессиях — фейковый шлюз.

## Готово, когда

1. `pytest -q`: интервью на фейковом шлюзе — старт, ответ текстом, ответ аудио (фейковый STT), выбор пробела по приоритету, «не знаю», лимит 8, «Хватит», финал, бюджет до вызова, `stt_failed`, отчёт по ссылке, удаление через 30 суток.
   Пробел «между шагами»: пара на передаче между ролями, порядок по посещениям и по порядку шагов, не больше 2, нет повтора после сдвига id, «ничего между ними» закрывает без вызова черновика, вопрос без цифр и ≤ 160 знаков, новые шаги из ответа доходят до финального Process; худший случай интервью не растёт.
2. `node --test web/`: отчёт (потери, первая автоматизация, эффект) совпадает с ручным счётом на фикстуре; ответы переопределяют допущения; `#report=` открывает отчёт.
3. `web/dev.html`: интервью на фейковом сервере (`scripts/dev_server.py`) целиком, на 360 px, светлая и тёмная, без микрофона.
4. `tests/test_hygiene.py` зелёный.
