# Процесс: как есть и как будет

Владелец рассказывает голосом или текстом, как у него идёт работа. Сервис задаёт до 8 вопросов: кто что делает, сколько заявок в месяц, где ждут. После каждого ответа схема по ролям дорисовывается. В конце код считает часы, рубли и дни на заявку, показывает, где теряется больше всего и что автоматизировать первым. Отчёт открывается по ссылке 30 суток. Схему можно скачать файлом .bpmn и открыть в Stormbpmn вместе с дорожками ролей.

Живое демо — [tavriq.ru/process/](https://tavriq.ru/process/).

**Статус на 2026-10-12.** Сервис и страница работают. Замера на 12 описаниях процессов из разных ниш ещё нет ([evals/](evals/)). Интервью проверено одним живым прогоном: 4 ответа текстом, 55 секунд, 1,34 ₽. Голосовой ответ на 11 секунд распознан за 1,2 с и стоил 0,16 ₽.

Собрано облачными сессиями Claude Code по [docs/SPEC.md](docs/SPEC.md) и [docs/SPEC-analyst.md](docs/SPEC-analyst.md): бэкенд, страница и замер писались параллельно по одному контракту API, приёмка и слияние — локально.

## Кто что решает

| Шаг | Кто |
|---|---|
| о чём спросить дальше | код ([app/gaps.py](app/gaps.py)): чего не хватает схеме и какой пробел сильнее всего влияет на часы и рубли |
| формулировка вопроса | `gemini/gemini-3.1-flash-lite`, цифры из вопроса код вычищает |
| голос → текст | `openai/gpt-4o-transcribe` |
| скрыть телефоны, почты и ссылки | код ([app/pii.py](app/pii.py)), до записи и до модели |
| заявки в месяц, ставка, минуты, ожидание из ответа | код ([app/understand.py](app/understand.py)), под вопросом видно, что записано |
| черновик схемы после ответа | `gemini/gemini-3.1-flash-lite`; у шага должна быть цитата из ответа, число без опоры код стирает ([app/checks.py](app/checks.py)) |
| финальная схема, роли, развилки и «Стало» | `anthropic/claude-haiku-5-5`, JSON по строгой схеме, без цифр ([app/pipeline.py](app/pipeline.py)) |
| часы, рубли, дни на заявку, потери, эффект первой автоматизации | код в браузере ([web/engine.js](web/engine.js)); у каждой цифры видно, из ответа она или допущение |
| схема и файл .bpmn | код в браузере ([web/engine.js](web/engine.js)) |

Ответы посетителя попадают в промпт отдельным блоком с пометкой, что это слова посетителя и инструкции из них выполнять нельзя. Финальный шаг при ответе не по схеме повторяется один раз; сломанный черновик пропускается, на схеме остаётся прошлый.

## Где ошибается

- Ставку код считает из месячной зарплаты: делит её на 168 часов. Налоги и взносы не добавляет, поэтому рубли выходят ниже настоящих.
- На четырёх записанных примерах время из текста нашлось у 5 шагов из 54. У остальных стоят допущения, 15 минут на задачу и 5 на решение. Часы и рубли — оценка порядка, а не хронометраж.
- У 6 шагов из 54 цитаты в тексте не нашлось: модель пересказала их своими словами или додумала. На странице у такого шага пометка.
- В первых записях модель считала клиента сотрудником, и его ожидание попадало в часы компании. Теперь клиент и поставщик помечены внешними, их время идёт только в дни на заявку.
- Очередь посчитана по простой модели: заявки приходят случайно, человек берёт их по одной. Пиковые дни, отпуска и срочные заявки без очереди она не видит.

## Как посчитано

- Сколько раз заявка проходит каждый шаг, считает поглощающая цепь Маркова по долям веток. Ветки развилки поровну, возврат на доработку 0,2.
- Часы в месяц = заявки × проходы × минуты по ручным шагам сотрудников, рубли = часы × ставка. Внешние роли в часы не входят.
- Загрузка роли = её часы / (люди × рабочие часы в месяц). Выше 0,85 — узкое место, от 1 очередь растёт без конца.
- Дни на заявку = время шагов + ожидание при передаче между ролями + очередь роли по M/M/1 на человека.
- «Стало»: шаг, отданный системе, занимает десятую часть ручного времени и не грузит людей. Убранный шаг выпадает, слитый прибавляет минуты к соседу.

## Как попробовать

```bash
pip install -r requirements-dev.txt
python3 scripts/dev_server.py        # фейковый шлюз, без ключа и денег: http://127.0.0.1:8765/dev.html

docker compose up -d --build         # порт 127.0.0.1:18106
curl -s 127.0.0.1:18106/api/process/status
```

Ключ и адрес шлюза Timeweb AI — переменные `LLM_API_KEY` и `LLM_BASE_URL` (в compose — файл `../llm.env`). Модели — `EXTRACT_MODEL`, `IMPROVE_MODEL`, `DRAFT_MODEL`, `STT_MODEL`. Контракт API — в SPEC.

Тесты: `pytest -q` и `node --test web/`. Замер — живые вызовы с потолком в рублях: `python3 -m evals.run --max-rub 2` — схема по описанию, `python3 -m evals.interview.run --max-rub 15 --dry-run` — интервью с владельцем-симулятором (с `--dry-run` только худший случай, без вызовов).

## Лимиты и данные

- 3 интервью в час с одного адреса, одновременно не больше 2. Ответ до 500 знаков или до 30 секунд записи. Интервью без ответа 10 минут закрывается.
- Дневной бюджет 40 ₽. Перед интервью код резервирует его худший случай, 12,70 ₽, после каждого вызова списывает настоящую цену ([app/pricing.py](app/pricing.py)).
- Ответы со скрытыми контактами и отчёт хранятся 30 суток, запись голоса не хранится. Адреса не хранятся, только хеш с солью для часового лимита.

## Структура

```
app/main.py           эндпоинты /api/process/*: разбор описания, лимиты, бюджет
app/interview_api.py  эндпоинты интервью
app/interview.py      ход интервью: ответ, черновик, следующий вопрос, финал
app/gaps.py           какой пробел спросить следующим
app/understand.py     числа из ответа: объём, ставка, минуты, ожидание
app/pipeline.py       описание → схема → проверка → «Стало»
app/checks.py         цитаты и числа против текста
app/gateway.py        шлюз: модели и распознавание речи
app/pii.py            маскирование контактов
app/pricing.py        цены вызовов и худший случай
app/store.py          SQLite: интервью, прогоны, расход, лимиты
app/recorded/         записанные примеры (статика, модель при показе не вызывается)
web/                  окно: process.js, engine.js (расчёт, раскладка, .bpmn), тесты node
evals/                замер схемы на 12 описаниях; evals/interview/ — замер интервью
scripts/              dev_server.py — сервер на фейковом шлюзе, record.py — запись примеров
```
