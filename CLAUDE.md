# demo-process — правила для сессий

- Что строим и критерии готовности — `docs/SPEC.md`. Контракт данных не меняй молча: если без правки не обойтись, опиши её в PR отдельным пунктом «Правка контракта».
- Ветка `feat/<кусок>` от `dev`, PR в `dev`. В `main` и `dev` напрямую не пушить.
- Перед каждым коммитом: `pytest -q` и `node --test web/` (когда есть `web/`). Python 3.12, зависимости — `requirements*.txt`; новую зависимость — только с причиной в PR. Для страницы зависимостей нет.
- Живых вызовов моделей нет: ключа в окружении нет, конвейер проверяется на фейковом шлюзе.
- Модули `app/gateway.py`, `app/pii.py`, `app/pricing.py`, `app/store.py`, `app/config.py`, `app/netutil.py` взяты из соседнего проекта (https://github.com/tavriq/demo-brief) — адаптируй под SPEC, тесты к ним там же.
- Не трогать `.claude/`, `.githooks/`, `LICENSE`.
- Репо будет публичным: без личных данных, почт и локальных путей. Запрещённые слова — вне репо (`~/.config/tavriq/stopwords` или `$TAVRIQ_STOPWORDS`), их читает `tests/test_hygiene.py`; тест держать зелёным, список в репо не класть.
- Коммиты по-русски: `feat:`, `fix:`, `test:`, `docs:`.
- В PR кратко: что сделано, команда тестов и её результат, что не сделано и почему.
